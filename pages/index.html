    음영 = 주입된 고장 구간(정답 라벨). 센서값은 SIMULATED SENSOR입니다.

    알림 로그

      Precision / Recall 비교 이번 실행

      창 단위 집계: 창의 50% 이상이 고장 구간이면 이상(1). 고장 경계에 걸친 창과 고장 종료 후 10 s는 제외 — 저장소 features/dataset.py, evaluation/metrics.py와 같은 규칙입니다. 지연 = 고장 시작부터 첫 이상 판정 창까지.

      저장소 오프라인 평가 같은 모델 · dataset v1 test split

      이 데모가 하는 것 / 하지 않는 것

      하는 것

      • 저장소의 Python 시뮬레이터(sim/)를 JavaScript로 옮겨 브라우저에서 50 Hz로 실행합니다. 노이즈가 없는 조건에서 Python과 궤적·안전 규칙 판정이 일치하는 것을 확인했습니다.
      • 센서 25 Hz / 5 Hz 가상 telemetry → 2 s 창 → 물리 잔차(디지털 트윈 잔차) 특징 83개 → 탐지기 4종. 특징 계산은 ai/twinpilot_ai/features/windows.py의 residual 세트를 옮긴 것입니다.
      • 탐지기 파라미터(정상 분포 통계, 임계값, Isolation Forest 트리 200개)는 저장소 학습 코드(training/train.py)로 학습해 JSON으로 내보낸 것을 그대로 씁니다. 브라우저 점수는 Python 점수와 상대오차 1e-9 이내로 같습니다.
      • Control Safety Layer(control/safety.py)의 비상 정지, 명령 타임아웃, 변화율 제한, 관절 한계, 전복 위험, 작업자 거리, 금지 구역 규칙을 그대로 적용합니다.

      하지 않는 것

      • 실제 장비 제어, 실제 센서 수집, 안전 인증, 실제 고장 원인 진단은 하지 않습니다.
      • 물리 모델은 근사(20 t급 가정)이며 검증된 장비 모델이 아닙니다.
      • 센서 노이즈 난수 생성기는 Python(PCG64)과 다릅니다. 분포는 같지만 값의 순서가 달라 실행 결과는 Python 데이터셋과 숫자 단위로 같지 않습니다.
      • 모델은 자동 조종(스크립트 조종기) 정상 데이터로만 학습했습니다. 수동 조종은 학습에 없던 패턴이라 오경보가 크게 늘어납니다 — 저장소 문서의 "미확인 조건" 한계와 같은 현상입니다.

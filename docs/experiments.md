# Experiments

형식: 가설 → 데이터 버전 → 모델 버전 → 학습 조건 → 평가 조건 → 기준선 → 결과 → 실패 원인 → 다음 실험

전체 표: [`eval/eval-v1.md`](eval/eval-v1.md) (재현: `uv run python -m twinpilot_ai.evaluation.evaluate`).
모든 결과는 시뮬레이션(Level 1) + 주입 고장 라벨 기준이다. 실제 장비 고장 진단 성능이 아니다.

공통 조건

- 데이터: `datasets/manifests/v1.yaml` — 126 run × 120 s (train 24 정상 / val 23 / test 53 / unseen 26), run 단위 분할
- 창: 2 s, stride 0.5 s. 라벨 = 창의 50% 이상이 고장 구간. 고장 종료 후 10 s와 부분 겹침 창은 평가 제외
- 임계값: val 정상 창 기준 FPR 1%로 보정. 경보 = 연속 2창
- 모델 선택은 **val F1**로만 한다. test·unseen은 선택에 쓰지 않는다

## 실험 1 — 이상 탐지 기준선 비교

- **가설**: 시계열 통계 특징 위에서 Isolation Forest가 고정 임계값·Z-score보다 낫다.
- **데이터**: v1 / **모델**: threshold-v1, zscore-v1, isolation-forest-v1 (NumPy 구현, 200 trees, ψ=256)
- **학습**: train 정상 5,688창. **평가**: test 53 run
- **기준선**: 고정 임계값(p99.5), Z-score(|z|>4)

| 모델 (full 특징 254개) | F1 | FPR | run 탐지율 | 지연 중앙값 |
|---|---|---|---|---|
| 고정 임계값 (val 보정) | 0.026 | 0.011 | 0.04 | 22.8 s |
| Z-score (val 보정) | **0.723** | 0.012 | 0.78 | 1.2 s |
| Isolation Forest | 0.000 | 0.011 | 0.00 | – |
| 고정 임계값 (보정 없음) | 0.355 | 0.284 | 0.87 | 1.2 s |
| Z-score \|z\|>4 (보정 없음) | 0.558 | 0.222 | 1.00 | 0.5 s |

- **결과**: 가설 기각. Isolation Forest는 FPR 1%에서 사실상 탐지 0. 교과서 임계값(보정 없음)은 재현율은 높지만 FPR 22~28%(시간당 오경보 160~240회)로 쓸 수 없다.
- **실패 원인**
  - IF는 매 분할마다 특징을 무작위로 고른다. 254개 중 고장과 관련된 특징은 몇 개뿐이고, 나머지는 조종 단계(주행/스윙/굴착)에 따라 크게 변한다. 정상 운전 변화가 고장 신호를 덮는다.
  - 고정 임계값은 min/max만 본다. JOINT_LAG·FRICTION은 값의 범위가 아니라 **명령 대비 응답**이 바뀌는 고장이라 범위 검사로는 안 보인다.
- **다음 실험**: 조종 단계에 덜 민감한 특징(물리 잔차·센서 건강 지표)을 만든다 → 실험 2.

## 실험 2 — 특징량 비교 (+ 개선)

- **가설**: 디지털 트윈 잔차(명목 모델 대비 편차)와 센서 건강 지표를 쓰면 조종 패턴 영향이 줄어 탐지가 좋아진다.
- **특징 세트**
  - `raw` 평균·min·max / `raw+delta` + 기울기·평균 절대 변화 / `raw+delta+rolling` + 표준편차
  - `full` = 위 전부 + 물리 블록
  - `residual` (83개) = 물리 블록만: 관절별 **twin residual**(명령으로 구동한 명목 1차 지연 모델 속도 − 측정 속도), command_error 크기, 위치 변화 vs 적분 속도 잔차, 센서별 `flat`(3회 이상 동일값 연속 길이), `hf`(2차 차분 크기, 노이즈 수준), 저속 채널 기울기
- **추가 모델**: `zscore-tail-v1` — 특징별 |z|를 그 특징의 정상 꼬리(p99.9)로 나눈 뒤 최댓값. 꼬리가 두꺼운 특징이 전체 임계값을 끌어올리는 문제를 줄이려는 목적.

| 모델 · 특징 | val F1 | test F1 | run 탐지율 | 지연 | 오경보/h |
|---|---|---|---|---|---|
| Z-score · raw | 0.088 | 0.082 | 0.18 | 4.6 s | 0 |
| Z-score · raw+delta+rolling | 0.455 | 0.324 | 0.40 | 2.0 s | 0 |
| Z-score · full | 0.741 | 0.723 | 0.78 | 1.2 s | 0 |
| Z-score · residual | 0.695 | 0.711 | 0.80 | 0.9 s | 26.2 |
| **Tail-Z · residual (선정)** | **0.807** | **0.828** | **0.91** | **0.8 s** | 6.7 |
| IF · residual | 0.011 | 0.034 | 0.31 | 5.1 s | 21.0 |

선정 모델 고장 유형별 (window recall / run 탐지율)

| 유형 | Tail-Z · residual | 주로 반응한 특징 |
|---|---|---|
| SENSOR_STUCK | 1.00 / 1.00 | `*.position:flat`, `*.velocity:flat`, `kin_residual` |
| SENSOR_NOISE | 0.91 / 1.00 | `*:hf` |
| TEMP_RISE | 0.71 / 0.89 | `hydraulic.oil_temperature:slope` |
| JOINT_LAG | 0.57 / 0.78 | `*.velocity:twin_absmean` |
| FRICTION_INCREASE | 0.48 / 0.89 | `*.velocity:twin_absmean`, `twin_mean` |

- **결과**: 가설 채택. 기준 Z-score(full) 대비 F1 0.723 → 0.828, run 탐지율 0.78 → 0.91. Z-score로 놓치던 TEMP_RISE가 window recall 0.09 → 0.71로 올라감. 특징 수는 254 → 83개.
- **미탐 4건 분석** (test)
  1. `JOINT_LAG swing_joint sev 0.9`: 고장 구간 동안 스윙 명령이 거의 없었다. 지연은 **움직일 때만** 드러나므로 관측 불가. 탐지 불가능한 경우와 실패를 구분하는 "관측 가능성" 라벨이 필요하다.
  2. `JOINT_LAG arm_joint sev 0.3`: 시정수 1.6배. 정상 조종 편차와 구분이 안 된다.
  3. `FRICTION swing sev 0.3`: 스윙은 관성 항이 커서 twin 잔차의 정상 분산이 크다.
  4. `TEMP_RISE sev 0.3`: 0.15 °C/s 상승. 2초 창 기울기 노이즈와 겹친다. 더 긴 창이나 열 모델 잔차가 필요하다.
- **오경보 원인 상위 특징** (test 정상 창): `oil_temperature:slope`(부하가 큰 구간의 자연 상승), 트랙·스윙 속도 `hf`(급가감속), IMU `hf`
- **IF가 계속 약한 이유**: 고장이 보통 특징 1~3개에만 강하게 나타난다. "특징 하나라도 극단이면 이상"인 max-z 계열이 이런 구조에 맞고, IF는 다차원 동시 이탈에 강하다. 실험 데이터가 IF에 불리한 구조임을 기록한다.
- **다음 실험**: 운전 조건이 바뀌어도 유지되는지 확인 → 실험 3.

## 실험 3 — 미확인 조건

- **가설**: 잔차 기반 특징은 운전 조건에 덜 민감해, 학습에 없던 조건에서도 성능이 유지된다.
- **평가**: unseen 26 run — 하중 1.5×, 조종 속도 0.6× / 1.4×, 동시 고장 2종. 모델·임계값은 실험 2 선정 모델 그대로 사용.

| 조건 | F1 | FPR | run 탐지율 | 오경보/h |
|---|---|---|---|---|
| 전체 | 0.851 | 0.033 | 0.96 | 58.7 |
| 동시 고장 | 0.954 | 0.012 | 1.00 | 0 |
| 느린 조종 0.6× | 0.952 | 0.003 | 1.00 | 10.8 |
| 무거운 하중 1.5× | 0.885 | 0.034 | 1.00 | 53.3 |
| **빠른 조종 1.4×** | **0.562** | **0.072** | 0.80 | **143.7** |

- **결과**: 부분 채택. 탐지력은 유지된다(run 탐지율 0.96). 하지만 빠른 조종·무거운 하중에서 FPR이 3~7배로 커진다.
- **실패 원인**: 오경보 상위 특징은 `boom_joint.effort:hf`, `chassis.vibration_rms:hf`, 스윙 `hf`. 빠른 조종은 고주파 성분을 늘리고, 무거운 하중은 effort 수준을 바꾼다. 정상 분포 자체가 이동한 것(covariate shift)이고, 학습 데이터의 조종 속도 범위(0.8~1.2×)를 벗어났다.
- **다음 실험**
  1. `hf` 특징을 명령 변화율·부하로 정규화한 조건부 특징
  2. 학습 데이터에 조종 속도 0.6~1.4×, 하중 1.0~1.5× 포함 (v2 데이터셋)
  3. 관측 가능성 라벨(고장 대상 관절이 움직였는지) 추가로 평가 정확도 개선
  4. 열 모델 잔차(유압 일률 대비 온도)로 약한 TEMP_RISE 탐지
